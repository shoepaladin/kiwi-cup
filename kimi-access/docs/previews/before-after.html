Kimi Access · Before / After — gen-icons vector-conflict fix · v0.2.3

The build no longer fights the vector drawables

The Acid Wire rework committed ic_k.xml, ic_more.xml, preview_mic.xml and preview_projects.xml as vector drawables, but tools/gen_icons.py still regenerated the same names as PNGs at build time — and build.sh step 0 only checked for ic_k.png, so every fresh build recreated the collision and aapt2 failed on duplicate resources. Now the generator emits only the launcher fallback PNGs, prunes stale raster leftovers on every run, and step 0 runs unconditionally. Artwork is unchanged — same vectors, same launcher icon; this PR changes tooling, not pixels. Version bumped 0.2.0 → 0.2.3.

1 · The build collision

What build.sh step 0 leaves in app/src/main/res before aapt2 runs.

Before — v0.2.0 tooling

$ ./tools/build.sh ==> [0/6] Icons (runs only if ic_k.png is absent) $ python3 tools/gen_icons.py res/drawable/ ic_k.xml # committed vector ic_k.png # regenerated — same name! ic_more.xml ic_more.png # collision preview_mic.xml preview_mic.png # collision preview_projects.xml preview_projects.png # collision ==> [1/6] aapt2 compile resources error: duplicate resources: drawable/ic_k (ic_k.xml vs ic_k.png) … build fails
Gitignored PNGs also linger in old working trees, so even a skipped step 0 didn't protect long-lived checkouts.

After — v0.2.3 tooling

$ ./tools/build.sh ==> [0/6] Icons (always runs — sub-second) $ python3 tools/gen_icons.py writes mipmap-*/ic_launcher.png # API<26 fallback prunes drawable/ic_k.png … # stale leftovers res/drawable/ ic_k.xml # vectors are the only ic_more.xml # source of these names preview_mic.xml preview_projects.xml ==> [1/6] aapt2 compile resources ==> [2/6] aapt2 link … no duplicates — build proceeds
Deterministic and self-healing: every build starts from the committed vectors plus freshly generated launcher fallbacks.

2 · The four drawables — generated raster vs committed vector

What the old generator emitted (old cream-and-orange identity) vs what ships now. Nothing changes visually in this PR — the vectors were already on main; the build simply stops re-adding their raster predecessors.

3 · Unchanged — launcher fallback & version

Pre-API-26 launchers still get code-drawn PNG mipmaps (ink tile, cream K, orange dot) — regenerated every build, never committed. Adaptive icon (API 26+) and all in-app glyphs are vectors.
